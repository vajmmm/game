# 00 - 总体项目路线图

## 为什么做这个项目

你已经完成了《图灵完备》的 CPU 关卡，亲手从逻辑门搭到了能跑机器码的 CPU。这个过程给了你两样东西：

1. **对"计算机怎么工作"的直觉** —— 取指、译码、执行、写回，你都在游戏里见过。
2. **对"分层抽象"的理解** —— 门 → 电路 → ALU → 寄存器 → 内存 → CPU → 指令，每一层都建立在上一层之上。

写模拟器是把这套直觉翻译成代码。在游戏里你用拖拽连线造 CPU，现在你要用 C 语言的 struct、数组、switch 语句模拟同样的东西。核心逻辑完全一样，只是表达媒介变了。

## 为什么选 CHIP-8

| 维度 | CHIP-8 | 真实 CPU (如 6502) |
|------|--------|-------------------|
| 指令数 | ~35 条 | ~56 条 |
| 指令长度 | 固定 2 字节 | 变长 (1-3 字节) |
| 内存 | 4 KB | 64 KB |
| 寄存器 | 16 个 8-bit | 3 个 8-bit + 特殊 |
| 显示 | 64×32 单色 | 复杂图形模式 |
| 文档质量 | 规范清晰、社区成熟 | 规范明确但细节多 |
| 测试 ROM | 丰富且简单 | 需要更多前置知识 |

CHIP-8 本身不是真实硬件，而是一个 1970 年代的虚拟机规范，设计用来在那些年的家用电脑上运行简单游戏。正因为它简洁、文档全，成了模拟器开发的入门标准。

## 技术选型

- **语言**: C
- **构建**: CMake
- **图形/输入库**: SDL2（跨平台，简单，CHIP-8 社区主流选择）
- **开发环境**: 你自行选择（VS Code、CLion 等均可）

SDL2 是什么：一个轻量 C 库，提供"创建窗口、画像素、读键盘"这几个能力。CHIP-8 只需要这三个功能，SDL2 刚好够用且不臃肿。

## 五阶段路线图

每个阶段都设计成"能跑、能看到结果"——不要攒一星期才看到东西。

### 阶段 1: 骨架与状态 (1-2 天)

**目标**：定义出 CHIP-8 的全部硬件状态，能在内存里加载 ROM 并打印出来。

你需要定义的东西：
- 一个 `uint8_t memory[4096]` 数组（主内存）
- 16 个通用寄存器 `V0..VF`（`uint8_t[16]`）
- 一个 `uint16_t I` 寄存器（地址指针）
- 一个 `uint16_t pc`（程序计数器）
- 一个栈 `uint16_t stack[16]` + `sp`（栈指针）
- 延迟定时器 `delay_timer` 和蜂鸣定时器 `sound_timer`
- 显示缓冲 `uint8_t display[64*32]`
- 一个 `uint8_t keys[16]` 数组（键盘状态）

完成标志：能读取一个 .ch8 文件到 `memory` 从 0x200 开始的位置，能用十六进制打印前 N 个字节验证加载正确。

### 阶段 2: 取指-译码-执行循环 (2-3 天)

**目标**：实现主循环，跑通第一个能"看着屏幕里像素变化"的程序。

CHIP-8 的每条指令都是 2 字节。主循环：
1. 从 `memory[pc]` 读 2 字节，拼成 `uint16_t opcode`
2. `pc += 2`
3. 用 `switch` 译码并执行 opcode
4. （稍后）重复，每秒约 600 次

这个循环跟你在图灵完备里搭的 CPU 核心循环**完全一致**：程序计数器指向内存中的指令，读出来、执行、前进。区别只是你现在用 `switch` 代替了硬件译码器。

先实现最少指令让一个测试 ROM 跑出画面：
- `00E0` (CLS 清屏)
- `1NNN` (JP 跳转)
- `6XNN` (MOV 设置寄存器)
- `7XNN` (ADD)
- `ANNN` (设置 I)
- `DXYN` (显示绘制——这一条会看到像素出现在屏幕上)

完成标志：跑经典的 IBM logo ROM 或 chip8 logo ROM，看到画面。

### 阶段 3: 显示与输入 (2 天)

**目标**：接上 SDL2，用真窗口显示 64×32 像素，能读键盘。

这一步把你的模拟器从一个"命令行打印数字的东西"变成一个"屏幕上能跑游戏的东西"。

- 初始化 SDL 窗口，大小如放大到 640×320（像素放大 10 倍）
- 把 `display[]` 数组映射到窗口像素
- 把键盘 1234QWER 映射到 CHIP-8 的 16 个键
- 每帧执行 N 条指令后更新画面、读键盘

完成标志：能跑 PONG、TETRIS 之类简单游戏，能用键盘控制。

### 阶段 4: 补齐指令集与测试 (2 天)

**目标**：实现剩余的指令，用测试 ROM 验证每条都正确。

到这时你已经有了一台能跑的机器，但很多指令还没实现——子程序调用 `2NNN`、条件跳转、逻辑运算、定时器、随机数等。一个个补上。

测试资源（社区里能搜到）：
- `chip8-test-suite`（用于验证指令行为）
- `BC_test.ch8`
- 经典 ROM（IBM Logo、Maze、Pong）

完成标志：通过 chip8-test-suite，能稳定运行 3+ 款经典游戏。

### 阶段 5: 优化与扩展思考 (开放式)

选项：
- 加入可变执行速度（滑块或按键）
- 加入调试器（单步、断点、查看寄存器）
- 实现现代解释器常用的 SUPERCHIP 扩展
- 用 Rust 重写一遍，对照体会所有权和模块设计
- 尝试 6502，体验真实 CPU 的复杂度

到这里你已经具备独立设计模拟器的能力。

## 怎么使用这套文档

按以下顺序读：
1. **本文档** (00) —— 全局视角
2. **01-chip8-architecture.md** —— CHIP-8 是什么、每个组件细节
3. **02-instruction-set.md** —— 所有指令的语义，写到代码里时查
4. **03-implementation-guide.md** —— 阶段 1-4 的逐步代码骨架
5. **04-testing-guide.md** —— 怎么验证、怎么调试

`02` 和 `04` 是参考手册性质的——实现时随时回查。`01` 和 `03` 是顺着读一遍再动手。

## 关于学习方式

这套文档不会给你完整答案，但会在关键处给足上下文和"该往哪里想"的提示。你写代码，文档负责指路。卡住了可以一起讨论。

每个阶段的"完成标志"是检查点——不是任务委托给你去做，而是帮你判断"自己是否真的到了这一步"。这点跟图灵完备很像：游戏只给你工具和目标，怎么造是你自己的事。
