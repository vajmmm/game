# 04 - 测试与调试指南

## 为什么单独一篇

模拟器有个特殊性质：**你的代码看上去能跑，但出错的后果可能是游戏在某帧画面错乱、某个角色穿模、某个游戏永远进不了下一关**。这类"行为错误但不会崩"的问题最折磨人，所以从一开始就要有测试节律。

不用上来写一堆单元测试——模拟器的单元测试价值有限（每条指令的行为依赖整体状态）。**靠测试 ROM 验证整体行为**远比写 `assert(chip8.V[0] == 5)` 高效。

## 测试 ROM 推荐顺序

按从简到繁：

### 1. IBM Logo（必跑）

显示 "IBM" 三个字。验证：
- ROM 加载正确
- CLS、JMP、LD I、LD Vx、ADD、DRW 全部工作
- display 数组最终有预期模式

通过标准：屏幕上能识别出 IBM。

### 2. chip8-test-suite（Timendus 出品）

社区目前最权威的测试套件。分多个场景：
- chip8 logo 显示测试
- 每条指令的行为验证
- 显示边界 / 碰撞 / 字体等专项

**用法**：跑各个子 ROM，对照它输出的"通/不通"画面，定位是哪类指令出问题。

### 3. BC_test.ch8

经典测试，覆盖算术 / 逻辑 / 进位 / 借位。比 test-suite 老，但简单，适合阶段 4 早期跑。

### 4. 简单游戏（Pong, Tetris, Tanks）

通过测试 ROM 后跑游戏。游戏是"集成测试"——任何指令在状态/时序上的细节错都会暴露成画面异常或控制失灵。

## 常见 bug 症状 → 对应排查方向

| 症状 | 可能原因 |
|------|----------|
| 屏幕完全空白 | ROM 没加载、pc 不是 0x200、draw_flag 没设、SDL 纹理更新位置错 |
| 画面糊成一团、不断闪烁 | `DXYN` 的 XOR 写错成赋值，或 VF 碰撞逻辑反了 |
| 程序立即 "Unknown opcode" | 字节序搞反：opcode 应该是 `(memory[pc] << 8) \| memory[pc+1]`，不是相反 |
| ROM 跑两步就崩 / 栈溢出 | `2NNN`/`00EE` 实现 did the right thing 检查：CALL 时 push 的是已经+2 的 pc |
| 数字显示不正常 | 字体不在 0x000-0x050，或 FX29 算地址用了错公式 |
| 键盘控制不灵 | keymap 顺序错、没有在事件循环里更新 keys 状态、FX0A 实现成"按下时拿到键"而不是"按下事件" |
| 游戏速度太快/慢 | 帧率循环不对；定时器没按 60Hz 递减 |
| 画面绕回位置不对 | DXYN 边界处理两种约定不一致，统一用取模或统一用裁剪 |
| `8XY6`/`8XYE` 行为有 ROM 通不过 | SHR/SHL 的 VY vs VX 两种约定，看 02 文档 |

## 调试工具：自建一个 trace 打印

最快的调试法是"看程序到底在干什么"。在 `chip8_step` 开头加：

```c
#ifdef DEBUG
printf("%03X : %04X  ", c->pc, opcode);
for (int i = 0; i < 16; i++) printf("%02X ", c->V[i]);
printf("  I=%03X SP=%d DT=%d ST=%d\n", c->I, c->sp, c->delay_timer, c->sound_timer);
#endif
```

然后编译时 `cmake -DCMAKE_C_FLAGS=-DDEBUG ..` 启用。把 trace 重定向到文件，对比不同模拟器的输出能快速定位分歧点。

更进一步的"寄存器快照 + 反汇编"留给阶段 5 的调试器扩展。

## 处理"方言差异"

跑到某些游戏时会发现一些指令行为模糊，CHIP-8 本身真的没有官方规范。处理原则：

1. 先按**传统约定**实现（见 02 文档的方言表）。
2. 跑 chip8-test-suite，看哪些指令被判为"和某种约定不符"。
3. 不要一上来就学多方言开关——会把自己的代码搞乱。**先单一约定，跑通多数游戏后再考虑加配置切换**。

## 关于"看到 bug 的瞬间"

模拟器调试有一个反复出现的模式：你在某帧看到画面错了一格像素、某个数字多了一位、某个球穿过了板。**这一帧往往不是 bug 的源头**——错误可能来自 1000 条之前的某条指令把寄存器写错了。

这跟图灵完备里调试电路的感觉类似：一个错位的门不会立刻报错，要到信号传到下一层你才发现画面不对。对应方法也类似：用 trace 打印定位"最早出现异常的 pc 位置"，而不是盯着当前帧看。这一招练熟了，以后调试任何复杂系统都用得上。

## 项目目录建议的就地放法

把测试 ROM 直接放在 `roms/` 下，结构示例：

```
roms/
├── ibm_logo.ch8
├── test_suite/
│   ├── 1-chip8-logo.ch8
│   ├── 2-some-other-test.ch8
│   └── ...
├── games/
│   ├── pong.ch8
│   └── tetris.ch8
└── bc_test.ch8
```

不要把 ROM 提交到你不希望托管的地方——它们是别人写的内容。自己用、自己保留就好。

也值得注意：测试 ROM 大多是社区里找得到的，自己搜就能下到，不需要走任何特殊渠道。
