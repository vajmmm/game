# 01 - CHIP-8 硬件架构

CHIP-8 是一个虚拟机规范，不是真实硬件。它在 1970 年代被设计用来让简单的游戏能在多种不同的家用电脑上运行——开发者只要针对 CHIP-8 写一次，就能在任何实现了 CHIP-8 的机器上跑。这跟 Java JVM 的思路类似。

所以你写模拟器，实际上是在"重新实现一个虚拟机的硬件"。CHIP-8 的所有"硬件"在你这里都是 C 语言的变量。

## 整体内存布局

CHIP-8 的地址空间是 12 位的，所以总内存 4096 字节（4 KB）。

```
0x000 +-----------------------+
      | 保留区 (解释器占用)     |  0x000-0x1FF  → 你的模拟器不能往这里放游戏代码
0x200 +-----------------------+
      |                        |
      |  ROM 加载区             |  从 0x200 开始放游戏程序
      |  (用户程序)             |
      |                        |
      +-----------------------+
      |  程序向上生长           |
      |  ...                   |
      |  ...                   |
0xFFF +-----------------------+
```

**规则**：
- ROM 永远从 `0x200`（512 字节）开始加载
- 程序计数器 `pc` 初始化为 `0x200`
- `0x000-0x1FF` 在原始硬件上是解释器，你的模拟器这里通常空闲——但 CHIP-8 约定十六进制字符的字体数据存在 `0x000-0x050`，需要你手动放进去（见下文）

## 字体

CHIP-8 程序可以在屏幕上画 16 个内置的 4×5 像素字体字符（0-F）。这些字体在原始硬件里存在 `0x000-0x050` 区域，每个字符占 5 字节（5 行，每行 4 位）。

你的模拟器启动时需要把这张字体表写入内存：

```
0xF0, 0x90, 0x90, 0x90, 0xF0,  // '0'
0x20, 0x60, 0x20, 0x20, 0x70,  // '1'
0xF0, 0x10, 0xF0, 0x80, 0xF0,  // '2'
0xF0, 0x10, 0xF0, 0x10, 0xF0,  // '3'
0x90, 0x90, 0xF0, 0x10, 0x10,  // '4'
0xF0, 0x80, 0xF0, 0x10, 0xF0,  // '5'
0xF0, 0x80, 0xF0, 0x90, 0xF0,  // '6'
0xF0, 0x10, 0x20, 0x40, 0x40,  // '7'
0xF0, 0x90, 0xF0, 0x90, 0xF0,  // '8'
0xF0, 0x90, 0xF0, 0x10, 0xF0,  // '9'
0xF0, 0x90, 0xF0, 0x90, 0x90,  // 'A'
0xE0, 0x90, 0xE0, 0x90, 0xE0,  // 'B'
0xF0, 0x80, 0x80, 0x80, 0xF0,  // 'C'
0xE0, 0x90, 0x90, 0x90, 0xE0,  // 'D'
0xF0, 0x80, 0xF0, 0x80, 0xF0,  // 'E'
0xF0, 0x80, 0xF0, 0x80, 0x80   // 'F'
```

`DXYN` 指令（绘制精灵）的 `N=4` 时会从 `I` 寄存器指向的位置读 5 字节来画字体——所以游戏要显示数字时需要先把字体地址塞进 `I`。

## 寄存器

### 通用寄存器 V0-VF

16 个 8 位寄存器，命名 `V0, V1, ..., VF`。`VF` 有特殊用途：

- **作为标志位**：`VF` 在 ADD/SUB 等运算后保存进位/借位标志（对应你在图灵完备里造的 carry flag）
- **绘制时的碰撞标志**：`DXYN` 指令在像素被翻转时把 `VF` 设为 1

注意：很多指令会"自动用到 VF"，所以游戏开发者通常不会用 VF 当通用寄存器。你的模拟器代码里 VF 的语义要严格遵守指令规范。

### I 寄存器

16 位，用作"地址指针"。很多指令会从 `I` 指向的内存位置读写数据。在图灵完备的语境里，这就像一个专门的"内存地址寄存器"。

### PC（程序计数器）

16 位，指向当前要执行的指令地址。每条指令 2 字节，所以执行后 `pc += 2`（除非这是跳转指令）。

### 栈和 SP

CHIP-8 支持 16 层子程序调用。`stack[16]` 存的是调用方的 `pc`，`sp` 是栈指针（指向下一个空位）。

- `2NNN`（CALL）：`stack[sp++] = pc; pc = NNN`
- `00EE`（RET）：`pc = stack[--sp]`

容量 16 层够用了——CHIP-8 游戏不深递归。

## 显示

**规格**：64 × 32 像素，单色 (每个像素只有 on/off 两种状态)。

你用 `uint8_t display[64 * 32]` 表示，1 = 亮、0 = 暗。原始 CHIP-8 显示通过 **XOR 精灵绘制** 实现，不要搞成"赋值":

- `DXYN` 指令：从 `(VX, VY)` 开始，把 `I` 指向的 N 个字节每个作为一个 8 位行画到屏幕
- 每个字节的 8 个位依次对应横向 8 个像素
- 像素 = 旧像素 XOR 新像素
- **如果像素被从 1 翻到 0**，设 `VF = 1`（称"碰撞"），否则 `VF = 0`

XOR 绘制是 CHIP-8 游戏移动精灵的标准技巧：在同一个位置画两次精灵会"擦除"它。

边界处理：原版 CHIP-8 会绕回（跨越右边界时画到下一行；穿越下边界时回卷到顶部），现代实现有不同选择，跟随 Cowgod's Chip-8 Technical Reference 是最稳的做法。

## 键盘

16 个键，编号 `0x0 - 0xF`。物理布局通常映射为：

```
物理键盘        CHIP-8
1 2 3 C    ←   1 2 3 C
4 5 6 D    ←   4 5 6 D
7 8 9 E    ←   7 8 9 E
A 0 B F    ←   A 0 B F
```

你可以按自己习惯。最常见映射是 `1234 / QWER / ASDF / ZXcv` → CHIP-8 键盘。

指令 FX0A 会暂停程序等用户按一个键。

## 定时器

两个 8 位定时器，每秒递减 60 次（约 60 Hz），减到 0 时停止（不会变负）。

- **Delay Timer** (`delay_timer`)：游戏用 `FX15` 设置、用 `FX07` 读取。常见用途：节奏控制。
- **Sound Timer** (`sound_timer`)：减到 0 时模拟器应当发出蜂鸣。游戏用 `FX18` 设置。可以简单实现成"当 `sound_timer > 0` 时持续播放一段音"或"在归零时发一声"。

**重要**：定时器的减法和指令执行是**独立**的。CHIP-8 经典运行模型是每秒执行约 600 条指令，同时定时器以 60 Hz 递减。如果你按 60 Hz 跑 CPU，游戏会慢得离谱。所以通常实现为：每帧（60Hz）跑 10 条指令 + 定时器减 1。

## 执行频率

CHIP-8 没有官方时钟频率。社区惯例：

- **CPU**: 约 600 Hz（每帧 10 条指令 × 60 帧/秒）
- **定时器**: 60 Hz

有些游戏假设更快的 CPU。你最好做成可配置（一秒跑多少条），用 +/- 键调整。

## 你的状态总览（C 结构体样子）

```c
typedef struct {
    uint8_t  memory[4096];      // 主内存
    uint8_t  V[16];             // V0..VF
    uint16_t I;                 // 地址寄存器
    uint16_t pc;                // 程序计数器
    uint16_t stack[16];         // 调用栈
    uint8_t  sp;                 // 栈指针
    uint8_t  delay_timer;       // 延迟定时器
    uint8_t  sound_timer;       // 蜂鸣定时器
    uint8_t  display[64 * 32];  // 显示缓冲
    uint8_t  keys[16];          // 键盘状态
    uint8_t  waiting_key;       // FX0A 等待的键 (0xFF = 不等)
    bool     draw_flag;         // 本帧是否需要刷新屏幕
} Chip8;
```

这就是你模拟器的"全部硬件"。整个项目本质上就是围绕初始化这个结构体、并让它按规则变化展开。
